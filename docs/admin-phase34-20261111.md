# تبسيط المشرف والإزالة — المرحلتان الثالثة والرابعة

## النطاق المعتمد

تعديل جراحي فوق مصدر رحلة العضو `39fea34` وتوثيق `dafec0d`. لا بناء جديد أو وكلاء أو اختبارات متصفح مرحلية أو نشر. قبل التطبيق حُفظت نسخة مصدر واستعادة D1 مشفرة ونشر وربطات حالية في نطاق مستقل. لا اختبار حذف على الإنتاج أو إرسال بريد أو تغيير DNS أو أسرار أو قفل أو أسعار أو دفاتر. تشخيص اللغة غير متاح للمستودع الخارجي بلا مشروع نشط؛ لا إعادة تهيئة، وتستخدم أنواع TypeScript والفحوص المحلية القائمة.

## المرحلة الثالثة: واجهة المشرف

خمس وجهات: المتابعة، الطلبات، الحسابات، المنصة، السجل. الأدوار وقواعد التفويض والخادم لا تتوسع بسبب عرض وجهة. تحت الطلبات تبقى المراجعات والعضوية والمدفوعات التاريخية، وتحت الحسابات الأعضاء والحسابات المدارة، وتحت المنصة المحتوى والخدمات والأسماء والتحويل والقفل، وتحت السجل التدقيق والحوكمة والنسخ والاقتصاديات. الوجهة الفرعية المختارة فقط ظاهرة، وتحميل البيانات عند دخولها؛ لا طلب كل الموارد عند فتح اللوحة.

قائمة الحسابات ثم بطاقة واحدة، بزر عودة على الجوال وعدم تكديس القائمة والبطاقة بالتتابع. النشر والمعاينة ظاهران، والعضوية والنقاط والخدمات والتفويض والإسناد والنشاط في أقسام مطوية اختيارية. كل وظيفة سابقة باقية. روابط `tab` القديمة تعيد القسم الصحيح وتُفحص صلاحيتها قبل فتحه. النشر بالزر القائم مباشرة، وطلب تعديل/رفض يتطلب سبباً كما كان؛ لا إضافة خطوة تحقق إلى النشر أو شروط ملف جديدة.

## المرحلة الرابعة: حذف موثق واضح

الحذف للمشرف الرئيسي فقط من بطاقة الحساب: اختيار الموقع وحده أو الحساب وجميع مواقعه، سبب، مراجعة الأثر والهدف، ثم زر تأكيد نهائي واحد. لا نسخ UUID ولا مربع موافقة إضافي؛ زر التأكيد هو الإرادة الصريحة. يرسل المكون المعرف الدقيق والإقرار ونسخ الحفظ وبصمة الأثر غير المرئية. تبقى المصادقة الحديثة وCSRF والحصانات والبلاغات وحماية حساب المالك في الخادم. لا إمكانية مباشرة لمشرف عادي أو مدير.

الإزالة تمس بيانات الهوية التشغيلية، المسودة واللقطة المنشورة وروابطها وحضورها، وتعطل الوصول والاعتمادات والجلسات وفق النطاق القائم. لا SQL DELETE/DROP، ولا محو دفاتر أو أحداث تاريخية أو شهادات قبول أو أدلة مراجعة غير قابلة للتعديل. تبقى المراجع الفنية الدنيا وسجلات الاحتفاظ، والملفات غير متاحة فوراً ويُتابع إتلافها المادي بطابور قائم؛ لا ادعاء محو كل نسخة احتياطية أو ملف فور الضغط. حصانات الاحتفاظ والبلاغ المفتوح تمنع التنفيذ ولا تُخفَّف بحجة مسؤولية المشرف.

البصمة الجديدة تلغي تأكيداً قديماً إذا تغير الحساب أو قائمة المواقع أو الوسائط، وتعيد العملية الذرية فحص عدد المواقع وارتباطها وأصداراتها ومجموعة الوسائط والحصانات والبلاغات. فشل الفحص لا يطبق تغييرات جزئية أو يعلن نجاحاً. تأكيد سابق بعد التنفيذ يرجع معرف الإثبات السابق ولا يعيد الإزالة. رد غير مؤكد في الواجهة لا يُعامل كنجاح.

## السجل ومسؤولية المنفذ

سجل التدقيق يبقى غير قابل للتعديل ومتسلسلاً ببصمات SHA-256 وتنقيح الأسرار والسبب الخام. سجل طلب الإزالة يحتفظ بالسبب ويرتبط بسجل المحاولة لمعرف المنفذ والهدف والوقت وبصمة الإثبات. تُعرض حالة طابور الملفات بأعداد المنجزة والمنتظرة وإعادة المحاولة، لا «محو شامل» مضلل. تُسجل مراجعة الأثر والمحاولة والرفض/الحصانة/تعارض البيانات والإخفاق/التنفيذ والتكرار دون أثر جديد. لا تسجيل لكل حرف أو مؤشر ولا إحياء القياس الاختياري المعطل. القرارات السابقة للنشر والعضوية والمنح والصلاحيات تستخدم سجلاتها القائمة، مع أسماء مفهومة وإثبات تقني اختياري في الواجهة.

## مسؤوليات الملفات

`admin-workspace.ts` خرائط عرض لا صلاحيات. `admin-workspace.css` معزول للمشرف والجوال. `Admin.tsx` يستثمر محركات التحميل والتعديل والنشر السابقة. `OwnerErasurePanel.tsx` خطوات قرار واضحة مع ردود قرائية مهملة عند تغير الهدف وحماية تكرار النقر. `OwnerErasureRecords.tsx` سجل مصادق يعرض الإثبات دون كشف مراسلات. `audit-copy.ts` ترجمة عرض لا تغيير أسماء أحداث التاريخ. `server/owner-erasure.ts` حراسات وسجل أثر ضمن نفس المسار القائم بلا ترحيل.

القبول محلي قبل حفظ المصدر. لا قبول بصري حي أو إتلاف مادي إنتاجي أو حذف حساب حقيقي في هذه الدفعة. النشر والقبول النهائي بالمرحلة السادسة، وسند والمحاذاة العامة بالمرحلة التالية، فلا تدّعى معالجة مشكلات لم تدخل النطاق.
