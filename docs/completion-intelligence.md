## دليل المصادر الفعلية (قراءة HTTP فقط، بلا متصفح وبلا كتابة)

تم الفحص المباشر في بداية المهمة بـ `GET` مع `Accept` خاص بـ RSS/Atom، لا بمنفذ متصفح ولا بمفتاح API:

| المعرف | النتيجة | نوع المحتوى | الحجم/البنية |
|---|---:|---|---|
| `hbr-arabic` | HTTP 200 | `application/rss+xml; charset=UTF-8` | 24,007 بايت، RSS، 20 بنداً مؤرخاً |
| `wamda` | HTTP 200 | `application/xml` | 104,198 بايت، RSS، 20 بنداً مؤرخاً |
| `forbes-middle-east` | HTTP 200 | `application/rss+xml; charset=utf-8` | 1,947,574 بايت، RSS، 500 بند مؤرخ |

وخلال أول اختبار حي مؤقت أعاد Forbes HTTP 500، فأنتجت الوحدة `partial` لا `ok`؛ وهو مثال مقصود لحالة الفشل الحقيقية. نجحت المحاولة التالية للخلاصات الثلاث في قاعدة D1 محاكاة فقط بنتيجة: `processed: 3`, `errors: 0`, `status: ok`, `inserted: 61`. هذه ملاحظة لحظية عن توافر الناشرين وليست ادعاء تشغيل إنتاجي أو كتابة إلى الإنتاج.

## عقد API ذي الصلة

- `GET /api/radar` يحتفظ بالحقول السابقة `link` و`published_date`، ويضيف أيضاً `url` و`published_at` المتوافقين مع المستهلك الحالي في الجوال، `659–672`.
- يضيف `status` و`reason` ويعرض لكل مصدر `lastFetched` و`lastError`، `673–685`.
- `POST /api/admin/radar/refresh` يعيد `ok|partial|unavailable` بصراحة، `688–693`.
- `POST /api/translate` لا يقبل طلباً بلا موافقة صريحة، ويعيد المسودة المحدثة وإصدارها عند حفظ ترجمة أو baseline صالح، `695–765`.

## إجراءات تكامل باقية للوكيل الأب

1. **واجهة الرادار:** `client/src/main.tsx` تستخدم حالياً `status === 'error'` للرسالة الفاشلة. يلزمها عرض `unavailable` و`partial` و`reason` و`lastError` بعبارة صادقة؛ فالخادم لا يعيد `error` لهذه الحالات. صارت حقول `url/published_at` متاحة للتوافق، لكن معالجة الحالات المرئية بقيت خارج نطاقي.
2. **واجهة الترجمة:** الـAPI يدعم `target: ar|en`، بينما لوحة المستخدم الحالية تستدعي الإنجليزية فقط. يلزم الوكيل الأب إضافة اختيار اتجاه عربي/إنجليزي واضح ومسار واجهة لتصحيح `draft.translations[target]` ثم الحفظ عبر عقد الملف القائم. لا ينبغي الإعلان عن ترجمة عكسية كواجهة مكتملة قبل ذلك.
3. **اختبار Workers AI الفعلي:** لم يُستدع نموذج AI من هذا العامل لأن ذلك يعتمد حصة Cloudflare المشتركة وقد يكتب مسودة. على الوكيل الأب تنفيذ fixture مصرح به بعد الدمج، بالموافقة الصريحة، والتحقق من حفظ نتيجة قابلة للتصحيح ومن بقاء اسم/مؤهل/منظمة رسمية كما هي.
4. **التغطية الجغرافية للمصادر:** المصادر المعتمدة الحالية ثلاثة ناشرين إقليميين وتطبع إلى `arab`. ترتيب السعودية/الخليج جاهز في الكود، لكنه لن يثمر عناصر بتلك الأولوية حتى يراجع المالك مصادر RSS سعودية/خليجية فعلية وشروط استخدامها ثم يضيفها الوكيل الأب بمراجعة للقائمة وترحيل لاحق. لا يجب وسم محتوى المصدر القائم كـ jobs أو سعودي من دون دليل عنوان/مصدر.
5. **النشر وقاعدة الإنتاج:** لم ينفذ هذا العامل أي cron أو refresh أو deploy حقيقي؛ بعد تكامل الأب فقط، يمكن التحقق من الحالة المحفوظة في `radar_sources.last_error/last_fetched` على بيئة مصرح بها ومقفلة.

## ملاحظة حدود الدليل

هذا تسليم للوحدة المحددة وليس إعلان اكتمال المنصة أو قبول بشري. دليل HTTP وتستات المحاكاة يثبتان منطق الوحدة في وقت التشغيل المحلي، ولا يحلان محل اختبار Cloudflare AI والإنتاج المقفل الذي بقي صراحة ضمن إجراءات الأب.
