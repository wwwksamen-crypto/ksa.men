# سند — تسليم التكامل وإعادة التصميم

## الملفات والدمج

الواجهة جاهزة في `client/src/Sanad.tsx` وتستورد نمطها المعزول من `client/src/sanad.css`. يدمجها المالك في `main.tsx` فقط:

```tsx
import Sanad from './Sanad';

// داخل App، بعد <main> وقبل <Footer>
<Sanad />
```

يجب حذف دالة `Sanad` القديمة المضمنة في `main.tsx` عند الاستيراد كي لا يتكرر الاسم. المكوّن لا يطلب شبكة، ولا يقرأ الحقول من DOM، ولا يستخدم `speechSynthesis`.

## سياق الصفحة

يستمع المكوّن للحدث `ksa:sanad-context` الذي يديره `sanad-context.ts`. يرسل Dashboard (أو أي صفحة) **أسماء حقول عامة وحالة واجهة فقط**؛ لا يرسل قيمة حقل، اسم مستخدم، بريد، نبذة، أو أي بيانات شخصية:

```ts
window.dispatchEvent(new CustomEvent('ksa:sanad-context', {
  detail: {
    section: 'editor',             // home | auth | editor | review | wallet | admin | qr
    step: 'identity',              // مفتاح خطوة أو مسماها العام
    requiredMissing: ['الاسم', 'المسمى'],
    state: 'editing',              // اختياري: editing | saving | saved | review | error
    saveStatus: 'saved',           // اختياري
    reviewStatus: 'draft',         // اختياري
    error: '',                     // رسالة مختصرة غير حساسة فقط
  },
}));
```

يمكن بدلًا من ذلك استيراد `publishSanadContext` من `./sanad-context`. عند عدم وجود `requiredMissing` أو كونها مصفوفة فارغة، لا يعلن سند اكتمالًا؛ يطلب مراجعة الحقول ودقتها. بذلك لا توجد نتيجة «مكتمل» ناتجة عن عد عناصر DOM أو قيم إدخال فارغة.

تبديل القسم أو الخطوة يوقف التسجيل الجاري؛ تغير حالة الحفظ التلقائي وحده لا يقطع الإرشاد. كذلك يحدث التنظيف عند الإغلاق، إخفاء الصفحة، وتفكيك المكوّن.

## الصوت والأصول

يحتاج Parent إلى وضع الملفات المسجلة (بنفس النصوص أدناه) في:

- `/public/assets/sanad/home-ar.mp3`
- `/public/assets/sanad/auth-ar.mp3`
- `/public/assets/sanad/editor-ar.mp3`
- `/public/assets/sanad/review-ar.mp3`
- `/public/assets/sanad/wallet-ar.mp3`
- `/public/assets/sanad/admin-ar.mp3`
- `/public/assets/sanad/qr-ar.mp3`
- `/public/assets/sanad/home-en.mp3`
- `/public/assets/sanad/sprites.webp`

الصورة `sprites.webp` شبكة 2×2: أعلى-يسار `neutral`، أعلى-يمين `speaking`، أسفل-يسار `large`، أسفل-يمين `blink`. يحلل المكوّن الصوت الحقيقي باستخدام `AudioContext` و`AnalyserNode` ويقيس RMS في كل إطار ليختار فمًا محايدًا أو ناطقًا أو مفتوحًا. لا يوجد تحريك كلام زائف. الحركة متوقفة افتراضيًا لمن يطلب تقليل الحركة، ويمكن للمستخدم تشغيلها أو إيقافها مع استمرار الصوت.

في العربية يختار سند التسجيل المناسب للقسم. في الإنجليزية يستخدم تعريف `home-en` العام. لا يتم نطق التوجيه الديناميكي؛ يظهر منفصلًا عن النص المسجل.

## النصوص المطابقة للتسجيلات

الأصول الصوتية الثمانية فعلية في public/assets/sanad. النصوص المصدرية المطابقة في docs/sanad-audio-scripts.json، وقد وُحّدت خريطة SANAD_AUDIO_SCRIPTS معها قبل النشر. اختيار الصوت العربي شبابي من الكتالوج العام، ولا توجد لهجة سعودية موثقة فيه؛ نعتمد النص المحلي ولا ندعي مطابقة صوت لهجي مثبتة.

## السلوك والوصول

- اللوحة Dock داخل التدفق العادي في جميع المقاسات، وليست فقاعة فوق الحقول أو CTA. يوجد فتح سريع من رأس الواجهة على الحاسوب ومن قائمة الهاتف.
- عند «إخفاء»، تحفظ `localStorage` التفضيل `ksa-sanad=hidden` وتبقى بطاقة إرشاد نصية داخل التدفق مع زر إظهار.
- تختفي اللوحة عند لوحة مفاتيح بصرية مفتوحة أو حوار آخر (`dialog` أو `[role=dialog][aria-modal=true]`) كي لا تغطي إدخال الهاتف أو CTA.
- النافذة هي عنصر `<dialog>` أصلي؛ يوفر حبس التركيز، وEscape، والطبقة الخلفية. الإغلاق يوقف الصوت ويعيده للبداية.
- عناصر التحكم: تشغيل، إيقاف مؤقت، متابعة، إيقاف، حركة تشغيل/إيقاف، إخفاء، وإغلاق. لا يبدأ أي صوت إلا بنقرة مستخدم.
- استخدام `<audio>` فعلي مع معالجة خطأ محلية؛ إذا لم يصل التسجيل بعد فتبقى الإرشادات النصية متاحة ولا يوجد بديل اصطناعي للصوت.

## تحسين النافذة

النص المسجل ضمن قسم قابل للتوسعة؛ عناصر الصوت متاحة دون مزاحمة نص طويل. تغلق النافذة تمرير الصفحة الخلفية وتعيده عند الإغلاق، وتحترم قيود الحركة في الجهاز. تستخدم لوحة الوجه صورة صغيرة مستقلة ولا تحمل أطلس الحركة حتى فتح الدليل.

## أصل الصوت

المقاطع المحلية لا تحتاج مفاتيح خدمة وقت التشغيل. يحمّل الصوت عند طلبه فقط، وتتحرر شبكة الصوت عند إخفاء الشخصية لتعمل حركة الفم بعد إظهارها مجددًا.
