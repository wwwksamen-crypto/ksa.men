# المرحلة الثانية — ضوابط الحوكمة والأمن والخصوصية

> وثيقة تشغيل داخلية. لا تُعرض داخل صفحات الزائر أو العضو.

## ما تطبقه الشيفرة

- **إعادة التحقق (fresh):** مطلوبة على الخادم قبل قرار المراجعة المؤدي للنشر، تغيير الدور، تعليق الحساب، منح الاستحقاق أو ضبط الخدمات، إجراءات التحويل والتسليم، إرسال الإشعارات الإدارية، قراءة سجل التدقيق، إعدادات المنصة، وإلغاء الأجهزة والجلسات أو تغيير PIN.
- **إدارة الجلسات والأجهزة:** تعرض APIs محمية تفاصيل زمنية مختصرة من دون رموز أو عناوين IP؛ الإلغاء يكتب سبباً، ويُلغي PIN أو الاسترداد جميع الأجهزة/الجلسات المتأثرة.
- **سجل التدقيق:** ترحيلة `0011_security_governance.sql` تجعل `audit` append-only وتربط السجلات الجديدة بـ SHA-256 عبر `prev_hash` و`row_hash`. لا تضع التفاصيل كلمات مرور أو PIN أو أكواد أو محتوى/نبذات أو صور أو أسباب حساسة؛ تحفظ بدلاً منها مؤشرات قليلة وبصمة HMAC داخلية عند الحاجة.
- **مفتاح النسخ:** `BACKUP_ENCRYPTION_KEY` مستقل إلزامي عن `AUTH_SECRET`. يسمح `BACKUP_ENCRYPTION_PREVIOUS_KEY` بالقراءة خلال نافذة تدوير مدروسة. لا تنشر أي نسخة قبل إضافة المفتاح إلى أسرار Worker.
- **DSAR والإتلاف:** `POST /api/privacy/hide` يخفي الموقع والبحث والتواصل والروابط فوراً. `POST /api/deletion-request` يسجل أحد خيارات الأرشفة، الإتلاف المجدول، أو الإتلاف النهائي بعد إقرار صريح وإعادة تحقق. الحجز النظامي/المالي/التدقيقي يمنع الإتلاف ويكتب حالة `blocked` بدلاً من حذف غير نظامي.
- **R2 والاحتفاظ:** حذف الوسائط صفّ durable في `media_purge_queue`؛ يبقي الطلب فاشلاً قابلاً لإعادة المحاولة إن لم ينجح R2. Cron ينفذ الإتلاف المجدول وينظف المحادثات `expired` المنتهية مدة الاحتفاظ عند عدم وجود بلاغ مفتوح.
- **Tombstones:** تسجل المعرّف ونوع المورد ووقت الإتلاف فقط. النسخ والاستعادة المعزولة تستبعد أي حساب/موقع/وسيط/محادثة/رسالة tombstoned تلقائياً.

## إجراءات تشغيل إلزامية قبل النشر

1. احفظ `BACKUP_ENCRYPTION_KEY` في أسرار Worker كقيمة عشوائية مستقلة 32+ بايت، وأضف المفتاح السابق فقط أثناء تدوير محدود؛ لا تضفه إلى Git أو `.dev.vars` المتعقب.
2. راجع سجل `retention_holds` مع المسؤول النظامي قبل إتلاف أي طلب محجوب. لا تُلغَ الحصانات من التطبيق تلقائياً.
3. عدّل سياسة الاحتفاظ في `settings.retention` بقرار موثق؛ Cron لا يطهر المحادثات غير المنتهية أو ذات البلاغ المفتوح.
4. استخدم رابط التحقق بالبريد قبل الإجراءات الحساسة، ولا تمنح مديراً مالياً إلا بعد توثيق تفويضه خارجياً.
5. اختبر الاستعادة فقط إلى ملف SQLite جديد ومعزول باستخدام `scripts/restore_snapshot.py`؛ لا توجد آلية استعادة مباشرة إلى الإنتاج.

## ROPA وخريطة تدفق البيانات

تُخزن السجلات القابلة للإدارة في `ropa_activities` و`data_flow_map`. تغطي سجلات البداية: الهوية والمصادقة، النشر المهني، والتواصل بالموافقة. تغطي خريطة التدفق: Cloudflare (Workers/D1/R2) وResend (رموز التحقق). يجب على مسؤول الخصوصية مراجعتها عند إضافة مزود أو فئة بيانات أو غرض معالجة.

## توطين البيانات: قيد تقني معلن

وفق توثيق Cloudflare الذي تم التحقق منه في 31 أكتوبر 2026، لا تدعم D1 أو R2 تلميح الموقع `me` للشرق الأوسط؛ كلاهما يذكر أن `me` غير متاح ضمن قيم Location Hint الحالية. كما أن الموقع/الاختصاص يختار عند إنشاء المورد ولا يُنقل للحاوية أو قاعدة البيانات القائمة. لذلك لم يُضف حقل Wrangler غير صالح ولن يُدّعى أن البيانات داخل المملكة. قبل أي التزام توطين، يلزم قرار معماري منفصل: إنشاء موارد مدعومة في موقع/اختصاص متاح ثم خطة ترحيل معتمدة أو اختيار مزود يحقق المتطلب التعاقدي والجغرافي المطلوب.
