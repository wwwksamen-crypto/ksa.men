# إعادة تصميم الإدارة — منضدة العمل

## النتيجة

تمت إعادة بناء واجهة `/admin` كمنضدة عمل إدارية هادئة ومركزة بدل شاشة ترحيب أو بطاقات تسويق أدوار. تحافظ الواجهة على جميع مسارات الإدارة الحالية، نماذجها، تحققها المحلي، وقرارات الخادم. لا يضيف هذا التغيير أي صلاحية في المتصفح ولا يغير الخادم أو البيانات أو المصادقة.

## البنية البصرية

- سطح إداري متوافق مع متغيرات التصميم المشتركة: `--bg` و`--surface` و`--surface-2` و`--text` و`--muted` و`--border` و`--accent` و`--gold` و`--green` و`--danger`، مع قيم احتياطية داخل نطاق الإدارة فقط.
- شريط علوي صغير يحمل العلامة، شارة دور واحدة فقط، تحديث الجلسة، وتحديث القسم الحالي.
- شريط جانبي ثابت على الشاشات بدءاً من `960px`، بعرض `232px` ثم `256px` بدءاً من `1200px`، ومجموعات واضحة: المتابعة، التشغيل، الحوكمة.
- قائمة إفصاح (`details/summary`) منظمة على الجوال بدلاً من شريط تبويبات أفقي طويل.
- بطاقات نظرة التنفيذية تقتصر على أربعة مؤشرات حية فعلية: إجمالي المستخدمين، المواقع المنشورة، طلبات المراجعة، وطلبات الدفع.
- صف انتظار موجز مبني على حقول ملخص الخادم فقط، وينقل المستخدم إلى قسم المعالجة المتاح وفق دوره.
- أرقام المؤشرات تستخدم `Intl.NumberFormat` مع تجميع للأرقام، وتعرض داخل `bdi dir="ltr"` لحماية اتجاهها وسط العربية.
- كل CSS يبدأ من `.admin-console`؛ لا توجد `:root` أو قواعد حقول عامة صادرة من ملف الإدارة.

## حدود تحميل البيانات

بيانات الإدارة أصبحت كسولة التحميل حسب القسم. الشاشة الأولى تطلب فقط `/api/admin/overview`. عند اختيار قسم مسموح، تطلب الواجهة فقط الموارد التي يحتاجها ذلك القسم:

| القسم | الموارد المطلوبة عند فتحه |
| --- | --- |
| النظرة التنفيذية | `/api/admin/overview` |
| المراجعات | `/api/admin/reviews` |
| المستخدمون | `/api/admin/users` و`/api/admin/services` |
| المدفوعات | `/api/admin/payments` ضمن التفويض المالي الموجود أصلاً |
| الخدمات | `/api/admin/services` |
| الأسماء | `/api/admin/names` و`/api/admin/transfers` |
| المحتوى / التسعير / القفل | `/api/admin/settings`، ثم مسار المحتوى المحدد عند فتح المحتوى |
| الاقتصاديات | `/api/admin/economics` |
| سجل التدقيق | `/api/admin/audit` |
| النسخ الاحتياطية | `/api/admin/backups` |

تظل البيانات المحملة في ذاكرة الصفحة عند التنقل، ويمكن إعادة تحميل القسم الحالي من الشريط العلوي. يظل تحقق الصلاحية الفعلي لدى الخادم؛ تصفية التبويبات مجرد تنظيم للواجهة وليست تفويضاً.

## أخطاء التحقق الحديث

خطأ تحقق حديث صادر عن إجراء حساس يبقى داخل القسم الذي أطلق الإجراء. يعرض التنبيه رابط **إعادة التحقق** إلى `/auth?reauth=1` بدلاً من تلويث صفحة النظرة التنفيذية الناجحة برسالة عامة. لا تحاول الواجهة إعادة الإجراء أو تجاوز رفض الخادم.

## سياق سند

تنشر الصفحة عند تبديل القسم أو تغير حالة الحفظ الحدث التالي دون أي معلومات شخصية أو محتوى مستخدم:

```ts
window.dispatchEvent(new CustomEvent('ksa:sanad-context', {
  detail: {
    section: 'admin',
    step: '<active tab>',
    requiredMissing: [],
    saveStatus: 'idle' | 'saving',
    reviewStatus: 'review' | 'none',
  },
}));
```

هذا يتيح لواجهة سند التي يدمجها Parent تقديم إرشاد إداري سياقي آمن.

## نقاط التكامل للـ Parent

1. لا يلزم تعديل مسارات الخادم أو واجهة `api` أو `AppContext` لهذا التغيير؛ كل أسماء المسارات والطلبات الحساسة القائمة بقيت كما هي.
2. يحتاج Parent فقط إلى إبقاء متغيرات التصميم العالمية المتفق عليها متاحة. الملف يملك fallback محدوداً داخل `.admin-console` لضمان قابلية القراءة أثناء الدمج.
3. يجب أن يستمر Parent في تركيب مكوّن `Sanad` العام ليستقبل حدث `ksa:sanad-context` المنشور من الإدارة.
4. لا توجد أصول جديدة أو تحميلات خارجية. الأيقونات تستخدم `lucide-react` الموجود مسبقاً.

## التحقق

تم تنفيذ فحص TypeScript مرة واحدة بعد التغيير:

```sh
pnpm typecheck
```

والنتيجة: ناجح (`tsc --noEmit`).

## ملاحظات متبقية

- لا تزال الاستجابة النهائية للصلاحيات والتحقق الحديث ومسارات النسخ الاحتياطي من مسؤولية الخادم، كما كانت قبل التغيير.
- الواجهة تعرض فقط الحقول التي يعيدها الخادم. إذا لم يعِد ملخص النظرة حقل صف انتظار، يظهر كـ «غير متاح» بدلاً من اختراع عدد.
